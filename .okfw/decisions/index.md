## Concepts

* [ADR-0001: A dedicated UAT repo that builds every tool from a pinned SHA](adr-0001-a-dedicated-uat-repo-that-builds-every-tool-from-a-pinned-sha--01a1caeb8cd0.md) - The UAT lives in its own repository and builds Vizzini, mrman, garmr and okfw from pinned commits, never from installed binaries or working trees.
* [ADR-0002: The mrman submit grant stays a human step](adr-0002-the-mrman-submit-grant-stays-a-human-step--01a1caeb8ce7.md) - The UAT never fakes a terminal to grant mrman's --auto submit; it pauses and a person runs the TUI with --auto.
* [ADR-0003: LiteLLM v1.99.4 with explicit max_tokens for the Claude 5.5 models](adr-0003-litellm-v1-99-4-with-explicit-max-tokens-for-the-claude-5-5-models--01a1caeb8cfe.md) - The proxy config pins max_tokens per model and sets drop_params, because Vizzini sends neither and LiteLLM's fallback would truncate reviews.
* [ADR-0004: The unattended leg authorizes by policy, deny first](adr-0004-the-unattended-leg-authorizes-by-policy-deny-first--01a1cbfe4052.md) - uat/bot.sh proves vizzini-bot posts with no person only under a garmr policy: the committed default must deny the PAT's identity, then a run-local copy listing the identity mrman verified with the forge must allow.
* [ADR-0005: Memory legs rerun and fix on the same PR](adr-0005-memory-legs-rerun-and-fix-on-the-same-pr--01a1cc2b9471.md) - uat/bot.sh proves thread memory on one live PR: a same-head rerun duplicates and resolves nothing, and after a pushed fix only the threads on the changed lines whose finding is gone are resolved.
* [ADR-0006: CI template tests run stubllm inside the job](adr-0006-ci-template-tests-run-stubllm-inside-the-job--01a1cf4af8c2.md) - The CI template tests replace the model with Vizzini's stubllm started inside the job, because hosted runners cannot reach the local LiteLLM and the template's wiring, not model quality, is under test.
* [ADR-0007: Azure Pipelines runs on a throwaway self-hosted podman agent](adr-0007-azure-pipelines-runs-on-a-throwaway-self-hosted-podman-agent--01a1cf4af8d2.md) - uat/ci-ado.sh runs the Azure Pipelines template on a self-hosted agent started in podman for the run, because the organization has no hosted parallelism, and grants and restores the build service's permission around it.
* [ADR-0008: GitLab CI runs on a throwaway self-managed GitLab CE in podman](adr-0008-gitlab-ci-runs-on-a-throwaway-self-managed-gitlab-ce-in-podman--01a1cf4af8e3.md) - uat/ci-gitlab.sh tests the GitLab template on a GitLab CE and gitlab-runner started in podman for the run, which needs no account or token and covers the self-managed path, at the cost of not covering gitlab.com.
* [ADR-0009: Cost attribution from LiteLLM spend logs, never prompts](adr-0009-cost-attribution-from-litellm-spend-logs-never-prompts--01a1cf4af8f4.md) - Every live run's cost is read from LiteLLM's Postgres spend logs keyed by Vizzini's request metadata; prompts and diffs are never stored there, and the requester identity is redacted in logs.
* [ADR-0010: Seeded fixtures per language; only must-catch defects are hard](adr-0010-seeded-fixtures-per-language-only-must-catch-defects-are-hard--01a1cf4af906.md) - Each language gets a seeded fixture with ground truth; the run fails only on harness invariants and must-catch defects, while recall, categories and severities are reported as metrics.
* [ADR-0011: Retry only what cannot have been applied](adr-0011-retry-only-what-cannot-have-been-applied--01a1cf4af917.md) - Network retries in the harness are limited to failures that happen before a request reaches the server, or to calls whose failure proves nothing was posted, so a retry can never post twice.
* [ADR-0012: The webhook test delivers locally, with events built from real Azure DevOps data](adr-0012-the-webhook-test-delivers-locally-with-events-built-from-real-azure-devops-data--01a1cf935aa6.md) - uat/webhook.sh runs vizzini-webhook on 127.0.0.1 and posts to it events in the exact service-hook shape, built from the real comment and PR, because Azure DevOps delivers only to public HTTPS endpoints; a delivery by ADO itself stays a manual case.
