# Code comments, help text and docs

## Comment style (AGENTS.md)

- Comments describe the code **as it is now**, for a future reader who knows nothing about the change that introduced it.
- Every exported type, function, field and constant has a godoc comment. It starts with the name and is a present-tense statement, for example `// Mkdir makes the directory (container, bucket)`.
- **Document the contract**: preconditions, return values, which sentinel errors come back and when, and caveats such as "shouldn't return an error if it already exists". Do not describe the implementation.
- Keep comments terse: usually one line, with extra paragraphs (separated by blank `//` lines) only for genuine subtlety.
- Inline comments explain **why**: an API quirk, a workaround, a gotcha or an ordering constraint. They may cite an external reference. Do not add comments that restate the code.
- Use `FIXME` and `TODO` for known shortcomings.
- **Do not narrate the change.** Avoid "now we also handle...", "changed to...", "previously this returned..." and bug or PR numbers in code. That information belongs in the commit message.

CONTRIBUTING.md asks AI-assisted contributors in particular to trim verbose comments down to this style.

## Option and flag help text

Backend options are documented in the `Help:` field of the Go options struct, not in markdown:

- The first line is a single sentence that ends with a full stop and is ideally under 80 characters. It becomes the flag help.
- More detail goes in a new paragraph after `"\n\n"`.
- Enumerations use `Examples:`. Each example's help is a list item and usually has no trailing full stop.

The rc option-block docs describe `Help` the same way: "started with a single sentence on a single line". Option blocks also carry `IsPassword` and `Sensitive` flags; `Sensitive` marks options that are redacted by `rclone config redacted`.

Command docs and flag help live in the command source, for example `cmd/ls/ls.go`. Flag help strings are a single sentence on one line **without** a trailing full stop.

## Generated vs hand-written docs

- `docs/content/commands/`, `docs/content/flags.md`, the `MANUAL.*` files and the marked `autogenerated` sections of backend pages are generated from Go source. Edit the `.go` file instead.
- Do not commit the output of `make backenddocs` or `make commanddocs`. A PR check reports changes inside autogenerated sections.
- A new general (non-backend) flag is documented by hand in `docs/content/docs.md`, in alphabetical order.
- Markdown is linted with markdownlint. Hugo header anchors differ from GitHub's (leading `-` is dropped), so links need checking with `make serve`.

## Commit messages

The first line is prefixed with the directory changed, such as `drive:`, and is written for users because it goes into the changelog. The body explains why the change was needed.
